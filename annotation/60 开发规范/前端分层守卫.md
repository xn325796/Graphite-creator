# 前端分层守卫

`src-tauri/tests/layering.rs` 是一组纯文本针扫描，钉住“前端只画不算”这条线。它扫描 `src/` 下 `.vue/.js/.mjs/.cjs/.jsx/.ts`，跳过 `node_modules`、`dist`、`.git`，扫到 0 个文件同样判失败。

## 三条断言

1. 领域词不得出现：`hjson`、`consumes`、`requirements`。
   - 2026-11-20 收窄：`hjson` 只看**代码**——`//`、`/* */` 注释与 `'hjson'`/`"hjson"` 引号字面量不命中。
     原因：命令契约 `project_convert_format(ext)` 把 `"hjson"` 变成合法参数，文件选择提示也要写
     `mod.hjson` 这个文件名。该针防的仍是「前端自己解析 HJSON」。另两枚针口径不变。
2. 跨界通道只允许 `invoke` 与 `listen`：不得出现 `fetch(`、`XMLHttpRequest`、`new WebSocket`。
3. 依赖豁免面：不得 import `pinia`、`vue-router`、`vitest`、`@tauri-apps/plugin-*`。

> [!warning] 注释基本不豁免
> `consumes` / `requirements` 是字面扫描，注释里写了同样命中；`hjson` 自 2026-11-20 起只扫代码。
> 要解释相关概念，用不含这些词的话写在本库里，解释本身留在 Rust 侧。

## 扫描边界

它是纯文本针，拦不住改名变量、拼接字符串或换拼写的同义概念。它钉的是“领域词以本来面目出现在前端源码里”这一最容易被 review 漏掉的走法；真正的字节契约仍由 `crates/` 的测试守着。

## 常见触发

- 把 Rust 侧文档或错误文案整段复制进 `.js` / `.vue`。
- 为了调试临时加 `fetch` 或 WebSocket。
- 引入 Pinia 做状态、Vue Router 做路由、Vitest 写前端测试。
- 安装 `@tauri-apps/plugin-opener` 一类插件后又忘了删。

> [!tip] 加依赖的正确流程
> 先改分层断言与方案口径，再改 `package.json`，最后才写 import。顺序反了必然红。验证命令见 [[构建与验证]]。

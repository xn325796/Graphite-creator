# 构建与验证

本页是本地开发与交接时的命令清单。所有命令都在仓库根 `Graphite-creator/` 下执行，Node 与 Rust 工具链需预先就绪。

## 前端

- `npm install`：安装依赖，运行时只应看到 `vue` 与 `@tauri-apps/api` 两个。
- `npm run dev`：Vite 开发服务器，浏览器打开后应看到默认 1200×650 的窗口（最小 960×600，可自由缩放）。
- `npm run build`：产物进 `dist/`，失败先看第一条报错。

## 桌面壳

- `npm run tauri dev`：拉起 Tauri 窗口；首次编译较慢，属正常。
- `npm run tauri build`：出安装包，发布前才需要。

## Rust 测试

Windows Git Bash 下先把 mingw 链进 PATH，再在仓库根跑全工作区测试：

```bash
export PATH="/c/msys64/mingw64/bin:$PATH"
cargo test --workspace
```

不要用 `--manifest-path src-tauri/Cargo.toml`：那条命令只编壳，会漏掉 9 个领域 crate（2026-11-25 冗余清理后为 9 个，原 mm-project 已删除）。
2026-11-25 基线：177 条通过（mm-io 54；mm-app 24：单元 10 + 集成 controller_flow 5 + cosmos_scene 9；壳侧 dto_contract 12 + fs_sprite 8 + layering 3 + sprite_import 7 + tech_forest 1；其余为各 crate 单元测试：mm-fmt 29、mm-layout 17、mm-validate 13、mm-json 6、mm-schema 3）。口径：gnu 工具链（stable-x86_64-pc-windows-gnu）、0 编译警告。同日 minGameVersion 回退值改动新增 1 条 mm-fmt 测试后为 178 条。
2026-11-26 基线（现行）：**228 条通过 / 0 失败**。分布——壳侧 52：window_close 19 + dto_contract 12 + fs_sprite 8 + sprite_import 9 + layering 3 + tech_forest 1；mm-app 39：单元 18 + controller_flow 5 + cosmos_scene 9 + sprite_import_undo 5 + script_class_inference 2；mm-io 59、mm-fmt 30、mm-validate 22、mm-layout 17、mm-json 6、mm-schema 3；mm-cli/mm-model 0。clippy **0 警告 0 错误**（存量 158 条唯一诊断已清零，16 条 allow 均就地登记理由）。增量来源：贴图导入进撤销栈、R-02 类解析（扫描/解析/`scriptClass` 校验/端到端）、校验器引用假阳性回归。

分层断言在 `src-tauri/tests/layering.rs`，可单独跑：

```bash
cargo test -p graphitecreator --test layering
```

> [!warning] 三条断言全绿才算过
> 任何一条红都说明前端越界，处理方式见 [[前端分层守卫]]；不要用改测试的方式让它变绿。

## 浏览器验证清单

- 画布无横向滚动条，控制台无报错。
- 六个页签可切换，cosmos/tech/canvas 首次进入即有内容。
- 修改字段后状态栏出现未保存，120s 内自动保存。
- F5 校验后 E/W 计数与日志同步；F6 能启动游戏。
- 切换语言后菜单、命令条、tooltip 全部更新。
- 关闭按钮只出现遮罩，重新打开后数据不丢。

> [!tip] 提交前
> `npm run build` 与 `cargo test --workspace` 都跑一遍；界面改动附一张截图说明前后差异。

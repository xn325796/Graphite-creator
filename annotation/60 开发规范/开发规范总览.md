# 开发规范总览

本目录收三条硬规范：前端分层守卫、注释与文档约定、构建与验证。它们共同回答一个问题——什么样的改动可以合入。

## 三条线

- [[前端分层守卫]]：`src/` 不许出现的词、通道与依赖，由 Rust 集成测试强制。
- [[注释与文档约定]]：源码只留必要注释，其余知识进本库。
- [[构建与验证]]：本地必须跑过的命令与浏览器验证清单。

> [!warning] 规范是断言，不是口号
> 分层的三条断言写在 `src-tauri/tests/layering.rs` 里，每次 cargo test 都会跑；注释约定靠 review；构建与验证靠交接清单复核。

## 改动前自检

1. 新代码是否把领域计算带进了 `src/`？
2. 新增依赖是否仍在 `vue` 与 `@tauri-apps/api` 的白名单内？
3. 新增模块是否补了对应笔记或同目录说明？
4. 是否引入了 vw/vh/scale/媒体查询？

## 与架构的关系

规范的存在意义由 [[架构总览]] 的分层决定：前端只画、Rust 才算。规范文件不重复架构内容，只给可执行的检查项；越界时先改设计，再改测试口径，最后才写代码。

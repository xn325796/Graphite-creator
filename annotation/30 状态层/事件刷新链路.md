# 事件刷新链路

壳通过事件主动通知前端。initEvents 在 home.vue 挂载时注册一次，六条事件覆盖项目变更、选择变更、校验结果、游戏日志、导入进度与关窗请求。

> **2026-11-26 就地更正**：原文写「五条事件」。z1 起是六条，新增 `window-close-requested`（空载荷）；
> 贴图导入与撤销重做带出的刷新口径也在这里补齐。依据：`src/store/project.js::initEvents`、`src-tauri/src/lib.rs::_EVENT_NAMES`。

## 六条事件

- `project-changed`：先 `refreshProject`，再 `refreshSelection`，使列表与检查器同步。
- `selection-changed`：携带选择载荷，直接 `applySelection`。
- `validation-refreshed`：调用 `refreshIssues` 重取 Issues。
- `game-log`：批量追加到 `S.logs`。
- `import-progress`：写入 `S.ui.importing`，done 达到 total 后清空。
- `window-close-requested`：原生 X / Alt+F4 / 应用内 `close()` 被壳拦下后广播，**空载荷**。处理见下节。

## 关窗链路（2026-11-26）

1. 壳在主线程拦 `CloseRequested`，`prevent_close`，`CloseGuard::request()` 发一代请求，广播 `window-close-requested`，并起 3s 兜底计时。
2. 前端 `onCloseRequested` 第一件事是调 `window_close_hold`：给该代打 hold 位，摘除兜底计时但**保留请求**；失败 `not-found` 静默。
3. 若 `S.dirty` 为假：清掉残留弹窗，直接 `window_confirm_close`。
4. 若 dirty：弹 `closeConfirm`（已有同种弹窗则不叠加、也不打断进行中的保存）。保存并关闭 → `save('save')` 成功且 `dirty` 清零后才 confirm；放弃并关闭 → 直接 confirm；取消 → 不调任何命令，窗口保持打开。
5. 兜底只对「无人 hold」的旧前端生效；`confirm` 与兜底对同一个原子字做 CAS，恰好一方赢。

状态机在 tauri-free 的 `src-tauri/src/close_guard.rs`，接线在 `lib.rs::run()`，前端在 `store/project.js::onCloseRequested`。

## 合并去重

`refreshProject` 用 refreshing/refreshAgain 两个标志合并并发请求：正在刷新时只记一次尾随刷新，当前轮结束后补跑一次。四路数据（summary/contents/history/strings）并行拉取，任一路返回 null 时按整体降级处理。

刷新成功时会 `clearCosmosScenes()` 并自增 `S.ui.cosmosRev`，让星球预览按新内容重拉（网格/外观/轨道都依赖内容快照）。刷新尾部按当前 workspace 补 `refreshTechFields`（科技树）或 `refreshBoard`（画布），保证切到对应页签时字段已就绪。

## 贴图导入与 undo 的刷新口径

- `sprite_import` 成功后：壳广播 `project-changed`（只重拉快照，不清缩略图缓存）；前端 `spriteImport()` 另把新 `dataUrl` 就地写进 `sprites` 缓存并记 `spriteImported`，随后主动 `refreshIssues()`，状态栏 E/W 与校验页不必等下一次手动校验。
- 撤销/重做可能改回磁盘上的贴图文件（导入已入撤销栈）：`doUndo/doRedo` 在 `settleSelection()` 后调 `invalidateImportedSprites()`，只作废「导入过」的记录并重拉，其余缩略图不动。
- 已知边界：极窄窗口下作废瞬间若仍有在途读取，可能把旧值写回缓存，下一次作废自愈（`invalidateImportedSprites` 的文档已登记）。

## 选择的落定

`applySelection` 带自增 `selSeq`，异步回包若序号已过期直接丢弃。`selRecord` 在 fields 到位后才原子赋值，避免检查器读到半成品；`selClassName` / `selClassSource` 同批写入（旧载荷缺 `classSource` 时按 `declared` 兜底）。`settleSelection()` 返回最近一次物化的 Promise。

`refreshSelection` 只刷新当前选中记录的数据，不抢选择权；旧 id 查询 not-found 时保持现状。

> [!info] 事件只注册一次
> 新监听必须挂进 `initEvents`，重复注册会导致同一次壳事件触发多轮刷新。

> [!warning] 清草稿前必须 await
> undo、重命名、raw 应用后若要清空草稿，必须先 `await settleSelection()`，否则草稿会按旧数据重建且不再刷新。

> [!tip] 新增刷新回调
> 与 `refreshProject` 同源的刷新应复用合并逻辑，避免事件风暴时叠加多轮全量拉取。

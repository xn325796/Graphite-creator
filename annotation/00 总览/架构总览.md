# 架构总览

GraphiteCreator 是一个“前端只画、后端才算”的桌面原型：画面由 Vue 3（`<script setup>` 单文件组件）配合 Vite 8 构建，运行在 Tauri 2 窗口里；领域逻辑全部落在 `src-tauri/` 与 `crates/` 的 Rust 侧。

> [!info] 一句话分层
> `src/` 只负责渲染，并把点击翻译成命令；`src-tauri/src/bridge.rs` 是唯一 IPC 门；`crates/*` 是模型、格式、校验与导出的真身，九个领域 crate 都不依赖 tauri。

## 技术栈

| 层 | 选型 | 约束 |
| --- | --- | --- |
| 视图 | Vue 3.5 `script setup` | 运行时依赖只有 `vue` 与 `@tauri-apps/api` |
| 构建 | Vite 8 | 开发用 `npm run dev`，产物由 `npm run build` |
| 外壳 | Tauri 2 | **45 条命令、6 条事件**（2026-11-26 实测），命令实现集中在 `bridge.rs`（目录浏览等纯外壳能力在 `fs_explore.rs`/`sprite_asset.rs`，关窗状态机在 `close_guard.rs`，都不依赖 tauri） |
| 领域 | 9 个 `crates/` | 零 tauri，测试守字节契约；第三方依赖只有 clap / thiserror / zip |

## 目录地图

- `src/views/`：`home.vue` + `home.css`，唯一页面壳。
- `src/components/layout/`：`MenuBar.vue` + `menubar.css`（标题栏、菜单、工具栏同住一个组件），另有 `PathPicker.vue`、`WindowResizer.vue`。
- `src/components/panels/`：AssetsListPane、UnitsPane、InspectorPane、CosmosPane、CosmosPreview、TechPane、CanvasPane。
- `src/components/ui/`：ArButton、ArInput、ArModal、ArTabs、ArCommandPalette、ArContextMenu 等 13 个 Argon 控件。
- `src/store/`：`project.js`（聚合状态 `S` 与全部动作）、`messages.js`、`schema.js`、`validate.js`。
- `src/lib/`：`ipc.js`、`toast.js`、`canvasGeometry.js`、`actions.js`（命令表单一来源）、`modalState.js`、`panelWidth.js`、`theme.js`、`window.js`、`cosmosRender.js`。
- `src/shared/`：只剩 `fieldDrafts.js`；样式在 `src/styles/`（`tokens.css` + `base.css`）。
- `src-tauri/src/`：`lib.rs`（命令注册）、`bridge.rs`（壳线程）、`dto.rs`（契约形状）、`close_guard.rs`（关窗代际状态机）、`forest.rs`、`fs_explore.rs`、`sprite_asset.rs`。
- `crates/`：mm-model、mm-schema、mm-json、mm-validate、mm-layout、mm-io、mm-fmt、mm-app、mm-cli（原第 10 个 mm-project 已于 2026-11-25 删除）。

## 启动链路

`index.html` → `src/main.js`（先引 `styles/tokens.css` 与 `styles/base.css`，再 `initTheme()`）→ `App.vue`（`.stage` 占满窗口，内含 `Home` 与 `WindowResizer`；1280×720 仅作设计基准）→ `views/home.vue`。`onMounted` 里依次执行 `initEvents()` 与 `openDemo()`：前者一次性订阅壳事件，后者载入演示项目；全局键盘监听也在这里注册（见 [[页面壳 Home]]）。

## 六条壳事件

`initEvents()` 订阅且只订阅这六条：`project-changed`、`selection-changed`、`validation-refreshed`、`game-log`、`import-progress`、`window-close-requested`（2026-11-26 新增，空载荷）。事件名由 Rust 侧常量单点拥有，前端只 `listen`，不自己拼字符串。第六条是原生关窗守卫的入口：前端收到后立即 `window_close_hold`，再按 dirty 决定直接 `window_confirm_close` 还是弹 `closeConfirm`（细节见 [[事件刷新链路]]）。

> [!warning] 别绕过壳
> 前端只允许 `invoke(...)` 与 `listen(...)` 两类跨界调用。自己发 HTTP、开 socket 或直接解析项目文件，都等于把领域逻辑搬回前端，`cargo test --test layering` 会直接红。
